# ZimAni TX 3.0 — замена контроллера пульта на NUCLEO-F429ZI

Этот комплект превращает NUCLEO-F429ZI в SPI-master, управляющий штатным радиомодулем пульта. Python-панель задаёт продольную команду, поворот, круиз, свет и подъём/опускание ножа. Плата управления робота остаётся штатной.

**Это первая версия для стендовой проверки.** Формат всех 1399 передающих пакетов из ваших записей воспроизведён точно; прошивка собрана для STM32F429ZI. Проверки на физическом радиомодуле и роботе здесь не проводились. Совпадение пакетов не доказывает правильную реакцию приводов, работу круиза или безопасность остановки.

## Что входит

- `Core/Src/main.c` — драйвер SPI3, радиомодуля, UART, таймеров и светодиодов.
- `Core/Src/zimani_control.c`, `Core/Inc/*.h` — формирование команд и правила разрешения управления.
- `build/ZIMANI_TX_v3.elf`, `.bin` — готовая прошивка; начало FLASH `0x08000000`.
- `pc/zimani_control.py` — Python-панель управления.
- `pc/zimani_protocol.py` — кодирование команд для своих Python-программ.
- `PROTOCOL.md` — формат команд, ответов и параметры радио.
- `tests/` — тесты и эталонные пакеты из записей.
- `standalone/` — необязательная сборка из командной строки с CMSIS из вашего проекта CubeMX.
- `VERIFICATION.md` — выполненные проверки и ограничения.

## 1. Переподключение радиомодуля

**Старая схема анализатора для этой прошивки не подходит.** Теперь STM32 сама выдаёт CSN, SCK, MOSI и CE. Модуль должен быть электрически отделён от контроллера штатного пульта: выключение питания его платы само по себе этого не обеспечивает. Иначе возможны конфликт выходов и питание выключенной платы через сигнальные линии. Удобнее извлечь модуль из разъёма и подключить его отдельно.

Уберите прежние ответвления CSN на несколько входов STM32 и ответвления SCK. Подключите каждый сигнал только по следующей таблице. Нумерация 1–8 соответствует присланной вами схеме радиомодуля; при пайке со стороны выводов изображение будет зеркальным. Сверяйте ориентацию по GND/VCC, а не только по расположению антенны.

| Контакт радиомодуля | Назначение | NUCLEO-F429ZI | Контакт CN11 |
|---|---|---|---|
| 1 | GND | Общая земля | 19 |
| 2 | VCC | Отдельное стабилизированное питание **3,3 В** | Не соединять с 5 В/VIN |
| 3 | CE | **PE3**, выход STM32 | **47** |
| 4 | CSN | **PA15**, выход STM32 | **17** |
| 5 | SCK | **PC10**, SPI3 SCK | **1** |
| 6 | MOSI | **PC12**, SPI3 MOSI | **3** |
| 7 | MISO | **PC11**, SPI3 MISO | **2** |
| 8 | IRQ | Не подключать; статус читается по SPI | — |

CN11 — длинный двухрядный разъём/ряд отверстий ST morpho, не CN9 и не надпись CAN. Номера CN11 взяты из UM1974, таблица 21. Если удобнее использовать существующие гнёзда Zio: PC10 = CN8-6, PC11 = CN8-8, PC12 = CN8-10, PA15 = CN7-9, PE3 = CN9-22. Это альтернативные точки тех же сигналов; соединять обе точки не требуется.

**Главное отличие от анализатора: MISO теперь на PC11, а CE добавлен на PE3.** PE6 для MISO здесь не используется. Три входа CSN объединять больше не нужно. CAN не используется.

Питание и монтаж:

1. Проводить пайку при отключённом питании STM32 и радиомодуля.
2. Модулю с усилителем нужен источник 3,3 В с запасом по пиковому току по его документации. Не предполагается, что выход 3V3 Nucleo способен питать ваш модуль с усилителем. Не подавать 5 В или напряжение аккумулятора пульта.
3. Соединить GND источника, радиомодуля и STM32. Не соединять между собой выходы двух стабилизаторов 3,3 В.
4. Рядом с VCC модуля поставить 100 нФ и 10–47 мкФ. Сигнальные провода сделать короткими.
5. Поставить **10 кОм CE–GND**: удерживает CE низким во время сброса STM32. Рекомендуется **10 кОм CSN–3,3 В**.
6. Антенна должна быть подключена перед передачей.
7. Nucleo подключить к ПК через верхний USB CN1 ST-LINK. Нижний User USB для этой прошивки не используется.

При раздельном включении питания не оставляйте активные сигналы STM32 на обесточенном радиомодуле. Перед любыми изменениями соединений отключайте оба источника.

## 2. Сборка и прошивка через STM32CubeIDE

Создайте отдельный проект, чтобы сохранить рабочий анализатор.

1. **File → New → STM32 Project**.
2. Во вкладке MCU Selector выберите **STM32F429ZIT6**. Название проекта, например `ZimaniTransmitter`. Тип проекта — STM32Cube, язык C.
3. Если открывается `.ioc`, сохраните его и выполните Generate Code. Специально настраивать SPI/UART/DMA в CubeMX для этой версии не нужно: их полностью инициализирует предоставленный `main.c`.
4. Замените **только `Core/Src/main.c`** файлом из архива.
5. Скопируйте `Core/Src/zimani_control.c` в `Core/Src`, а оба файла из `Core/Inc` — в `Core/Inc` проекта.
6. `startup_stm32f429zitx.s`, `system_stm32f4xx.c`, папку Drivers и линкерный файл оставьте сгенерированными CubeIDE. **Не вставляйте C-код в startup-файл.** Файлы из `standalone` в проект CubeIDE не копируйте.
7. Обновите дерево проекта клавишей F5. В Project Properties → C/C++ Build → Settings → MCU GCC Compiler → Optimization выберите **Optimize more (-O2)** для собираемой конфигурации. Убедитесь, что определён `STM32F429xx`; новый проект для F429 задаёт его сам.
8. **Project → Clean**, затем **Build Project**. В сборку должны попасть и `main.c`, и `zimani_control.c`.
9. Подключите USB CN1. Выполните **Run → Debug As → STM32 C/C++ Application** со ST-LINK/SWD. После загрузки нажмите **Resume**, если отладчик остановился в `main`.
10. Для самостоятельной работы завершите отладку и нажмите RESET B2 на плате. Не оставляйте процессор на breakpoint во время проверки приводов: штатный watchdog может перезапустить STM32 примерно через секунду.

Если переносить файлы в старый проект анализатора, там могут остаться обработчики прерываний и HAL-дескрипторы от прежнего кода. Чистый проект по инструкции выше избегает таких конфликтов. После замены main.c не запускайте повторную генерацию CubeMX поверх него: она может перезаписать реализацию.

Готовый `build/ZIMANI_TX_v3.elf` также можно загрузить через STM32CubeProgrammer, интерфейс ST-LINK. Для `.elf` адреса берутся из файла; для `.bin` укажите **0x08000000**, включите Verify и после записи Reset/Run. Этот образ предназначен только для STM32F429ZI с указанной разводкой.

## 3. Запуск Python-панели в Windows

Нужен Python 3.10+ с Tkinter (обычная установка Python для Windows включает его) и pyserial. PuTTY не нужен. Закройте прежний PowerShell-терминал/другую программу, занимающую этот COM-порт.

В PowerShell откройте папку `pc` распакованного архива:

```powershell
py -m pip install -r requirements.txt
py zimani_control.py
```

Можно указать порт и запись телеметрии:

```powershell
py zimani_control.py --port COM5 --log test_01.log
```

Замените COM5 номером **STMicroelectronics STLink Virtual COM Port** из Диспетчера устройств. Параметры 115200, 8N1 устанавливаются автоматически. Если команда `py` отсутствует, используйте `python`.

Порядок работы:

1. Включите STM32 и радиомодуль, затем робота в условиях стендовой проверки с отключённым силовым приводом. Штатная плата пульта от модуля отсоединена.
2. Выберите COM-порт → **Подключить**. STM32 уже повторяет нейтральные пакеты; подключение Python само по себе движение не разрешает.
3. Дождитесь `radio=1`, свежего `link_ms` менее 300 мс и увеличения ACK либо числа ответов BB. `radio=1` означает успешную проверку регистров по SPI; **не означает**, что робот принял команду движения.
4. Нажмите **Разрешить управление**. Сначала посылается нейтраль, элементы управления включаются только после подтверждения `armed=1` от STM32.
5. Проверьте каждую функцию отдельно на малой величине команды, затем направления и сочетания осей.

| Элемент | Действие |
|---|---|
| Продольная ось | −255 назад, 0 нейтраль, +255 вперёд |
| Поворот | −255 влево, 0 прямо, +255 вправо |
| Поле джойстика | Удерживать мышь и перемещать; отпускание возвращает оси в центр |
| Ползунки | Удерживают выбранное значение после отпускания мыши |
| Круиз | Передаёт предполагаемое поле p[18]; при отпускании мыши на поле сохраняет продольную команду, поворот сбрасывает |
| Свет | Передаёт предполагаемое поле p[17] |
| Поднять / опустить | Удерживать мышью; отпускание снимает команду изменения высоты |
| Красная кнопка / пробел | Снять разрешение, обе оси 0, нож 0, круиз 0, свет 0 |
| Кнопка B1 на Nucleo | Снять разрешение непосредственно в STM32 |

Потеря фокуса окна снимает разрешение. После возврата к окну нажмите «Разрешить управление» снова. При снятом разрешении все подвижные команды обнуляются; значение неизвестного p[9] сохраняется. Ползунки задают условную величину команды, а не скорость в м/с или угол поворота.

## 4. Индикация и диагностика

| Светодиод Nucleo | Значение |
|---|---|
| LD1 зелёный, PB0, короткая вспышка раз в секунду | Новая прошивка работает, управление не разрешено |
| LD1 зелёный постоянно | Управление разрешено |
| LD2 синий, PB7 | Радиомодуль настроен и недавно был ACK либо проверенный ответ BB |
| LD3 красный, PB14 | Ошибка/защитная остановка; причину смотреть в Python |

При снятом разрешении после нажатия «Подключить» красный может погаснуть, даже если робот выключен: смотрите также `link_ms`, `ACK`, `rx` и синий светодиод. Синий показывает подтверждение связи, а не работу моторов. Светодиоды ST-LINK и Power не управляются этой программой.

- `radio=0`, красный: проверить питание 3,3 В, GND, CSN/SCK/MOSI/MISO, ориентацию разъёма. Радиоинициализация повторяется раз в секунду.
- `radio=1`, ACK=0, `fail` растёт: проверить CE, антенну, питание робота и совпадение параметров радиоканала. В этой версии зашиты адрес и идентификатор именно из ваших записей.
- ACK растёт, `rx=0`: подтверждения радио есть, но прикладные ответы BB пока не получены; это не доказательство исполнения команд.
- `fault=2`: более 250 мс нет свежих корректных команд от ПК.
- `fault=3`: более 300 мс нет подтверждения связи при разрешённом управлении.
- `fault=5`: нужно снять разрешение и разрешить снова из нейтрали.
- `fault=6`: ошибка UART/DMA; проверьте соединение, затем при необходимости перезапустите STM32.
- `fault=7`: нажата B1.

## 5. Что установлено по записям и что ещё нужно подтвердить

Подтверждены структура 26-байтного TX-пакета, байты направлений/величин осей, команды высоты 0/1/2, контрольная сумма и рамка. Передатчик формирует новые пакеты из текущих значений; не воспроизводит старую последовательность SPI вслепую. Служебные чтения статуса могут отличаться от исходных, полезная нагрузка соответствует найденному формату.

**Свет p[17] — гипотеза:** записи `light_on` и `neitral_01` совпали, поэтому однозначного доказательства назначения нет. **Круиз p[18] — сильная гипотеза**, но единица также присутствует в записи `forward_left`, хотя в легенде круиз выключен. Элементы управления реализуют эти поля; их физическое действие следует подтвердить.

p[9] принимал 0 и 2, его назначение не установлено. По умолчанию используется 2, как в ряде записей нейтрали/торможения/диагоналей. В панели можно выбрать 0 при снятом разрешении, чтобы сравнить поведение. Код не пытается выводить значение этого поля из направления движения.

Нож: реализовано **изменение высоты**, не вращение ножа и не установка абсолютной высоты. Поле r[12] ответа показано в сыром BB-пакете, но не используется как достоверная обратная связь положения. Нужен отдельный датчик/расшифровка, чтобы задавать «высота 50 мм».

Частота обновления задана примерно 50 Гц. В исходных файлах не было временных меток, поэтому точное воспроизведение временных интервалов не заявляется. При повторных радиопередачах частота может снизиться. Python/Tkinter/Windows также не гарантируют жёсткое реальное время.

## 6. Остановка и границы защиты

При закрытии панели, потере фокуса, паузе её цикла более 200 мс или отсутствии обратного статуса около 700 мс Python снимает разрешение. STM32 независимо снимает его при отсутствии свежих команд 250 мс и связи 300 мс. После таймаута/сброса непрерывный поток старых ARM-команд не включает движение: требуется новый переход через снятое разрешение и нейтраль.

При снятии разрешения STM32 продолжает посылать нейтральные пакеты. Если радиообмен исправен, новый пакет обычно уходит в следующем цикле; уже начатую передачу/аппаратные повторения предыдущего пакета мгновенно отменить нельзя. При потере радиоканала или питания **доставка нейтрали невозможна или не гарантируется** — остановка робота зависит от его собственного watchdog/failsafe. В записанном протоколе отдельная надёжно установленная команда аварийного останова отсутствует.

До подключения приводов проверьте нейтраль, направления, кнопку STOP, отключение USB, потерю питания передатчика и потерю радиоканала. Для движущегося робота нужен независимый доступный способ снятия питания приводов. Эта программа не заменяет аппаратный аварийный останов.
