# ZimAni TX v3 — интерфейсы

## ПК → STM32: бинарная команда v1

USART3, PD8 TX / PD9 RX, ST-LINK VCP, 115200 8N1. Размер кадра 22 байта. Многобайтные числа little-endian. В штатной панели период отправки около 20 мс. Текстовые команды анализатора `a/s/d/h` здесь не работают.

| Смещение | Размер | Поле |
|---|---|---|
| 0 | 2 | Синхронизация C3 3C |
| 2 | 1 | Версия 01 |
| 3 | 1 | Тип команды 01 |
| 4 | 4 | Session, uint32, ненулевое случайное значение на каждое открытие порта |
| 8 | 4 | Sequence, uint32, увеличивается на 1 для каждого нового кадра |
| 12 | 2 | Forward, int16: −255…+255 |
| 14 | 2 | Turn, int16: −255…+255, положительное = вправо |
| 16 | 1 | Высота: 0 отпустить, 1 опустить, 2 поднять |
| 17 | 1 | Биты 0 ARM, 1 cruise, 2 light; остальные 0 |
| 18 | 1 | Неизвестный p[9]: 0 или 2, по умолчанию 2 |
| 19 | 1 | Резерв, 0 |
| 20 | 2 | CRC16-CCITT-FALSE байтов 0…19; polynomial 1021, init FFFF, xorout 0000, refin/refout false |

Проверка CRC: строка ASCII `123456789` → 29B1. Контрольная сумма кодируется LE.

Правила приёма:

- Новая session принимается только с ARM=0; при этом управление снимается.
- В существующей session принимается только последовательность, для которой `0 < (new-old) mod 2^32 < 2^31`. Дубликаты и старые кадры не обновляют watchdog.
- Сначала нужен кадр ARM=0, затем ARM=1 при нулевых осях, blade=0, cruise=0 и свежем подтверждении радио. GUI дожидается подтверждения armed=1 перед передачей ненулевых команд.
- ARM=0 игнорирует ненулевые оси/функции в кадре, обнуляет команды и разрешает новую процедуру включения. p[9] можно менять в этом состоянии.
- Изменение p[9] при ARM=1 снимает разрешение.
- Таймаут свежих команд 250 мс; таймаут ACK/проверенного BB 300 мс. Для разрешения после остановки нужен новый ARM=0 → ARM=1.
- Отдельного времени формирования кадра на ПК нет. Не ставьте команды в очередь заранее и не воспроизводите старый UART-поток: передавайте только последнее состояние.

`pc/zimani_protocol.py` содержит `Command`, `encode`, `parse_status` без побочных действий с COM-портом. Пример формирования одного кадра (не отправляет его):

```python
from zimani_protocol import Command, encode
frame = encode(session=123, sequence=10,
               command=Command(forward=50, turn=-20, armed=True,
                               blade=0, cruise=False, light=False, p9=2))
print(frame.hex(' '))
```

## STM32 → ПК: текстовый статус v3

Раз в 200 мс идёт строка ASCII `S v=3 ...\r\n`. При старте также выводится строка версии. Не смешивать бинарные команды с текстовым терминалом, который добавляет CR/LF.

| Поле | Смысл |
|---|---|
| session, seq | Последний принятый корректный кадр, включая отклонённую попытку ARM |
| armed | 1 — разрешено; 0 — нейтраль |
| radio | 1 — прошла настройка и проверка регистров радио по SPI |
| fault | Причина текущего состояния; 0 нет, 1 boot, 2 host timeout, 3 link timeout, 4 radio/SPI, 5 arm rejected, 6 UART/DMA, 7 B1 |
| host_ms | Возраст последнего корректного кадра; 999999 если нет свежего |
| link_ms | Возраст последнего TX_DS/ACK или валидного BB; 999999 если связь устарела |
| ack | Число TX_DS (с EN_AA=1 — получено аппаратное подтверждение) |
| fail | Число MAX_RT/таймаутов TX |
| rx | Число валидных 23-байтных BB-пакетов |
| badrx | Неверный размер/формат/идентификатор/сумма принятых пакетов |
| reject | Отклонённые кадры ПК, включая старый sequence и ошибки синхронизации/CRC |
| uart, spi | Счётчики обнаруженных ошибок UART/DMA и радио/SPI |
| f, t, blade, cruise, light, p9 | Текущее состояние команды, из которого формируется TX |
| rx_ms, reply | Возраст и HEX последнего корректного BB; `-`, если его ещё не было |

ACK подтверждает радиодоставку, но не исполнение двигателями. reply может быть старым — смотрите rx_ms. Ответы BB проверяются по длине, маркерам, идентификатору и сумме; смысл всех телеметрических байтов пока не установлен.

## STM32 → радиомодуль

SPI3 master, mode 0, MSB first, 8 бит, около 1,3125 МГц. GPIO CE — PE3, CSN — PA15. PC10 SCK, PC12 MOSI, PC11 MISO. USART3_RX DMA1 stream1 channel4; TIM5 даёт микросекунды. HSI → PLL 168 МГц, APB1 42 МГц. Уровни 3,3 В. HAL не используется в рабочем цикле.

| Регистр | Записываемое значение |
|---|---|
| CONFIG | 08 при настройке, 0A для TX, 0B для RX; аппаратная CRC 1 байт |
| EN_AA | 01 |
| EN_RXADDR | 01 |
| SETUP_AW | 03 (5 байт) |
| SETUP_RETR | F3 (4 мс, до 3 повторов) |
| RF_CH | 45 (2469 МГц) |
| RF_SETUP | 23 (250 кбит/с, значение из записи) |
| TX_ADDR | F8 C4 20 43 4E — порядок байтов на SPI |
| RX_ADDR_P0 | F8 C4 20 43 4E |
| RX_PW_P0 | 17 (23), при DPL размер читается динамически |
| DYNPD | 01 |
| FEATURE | 07 |

Если FEATURE не записался, выполняется ACTIVATE `50 73`, затем повторная запись и проверка. Не предполагается универсальная поддержка всех клонов радио; при несовпадении прочитанных регистров radio=0, движение запрещено.

После PWR_UP выдерживается 5 мс. Для TX загружается `A0` + 26 байт, CE удерживается высоким не менее 20 мкс. STATUS опрашивается; после TX_DS либо ошибки передатчик переходит в RX и принимает ответы через `60`/`61`. RX-FIFO обрабатывается и до смены TX→RX, поэтому поддержан как ACK-payload, так и отдельный ответ робота. На следующем цикле загружается актуальное состояние. Минимальное окно RX — 3 мс; целевой период TX — 20 мс. Таймаут TX — 20 мс; при неудачах период увеличивается. Точное исходное расписание CE по имеющимся записям неизвестно.

## Полезная нагрузка команды: 26 байт

p[i] считает байты ПОСЛЕ команды SPI A0.

| Байты | Содержимое |
|---|---|
| p[0] | AA |
| p[1…8] | F8 C4 20 00 43 4E 1D 04; фиксированная часть из ваших записей |
| p[9] | 0 или 2, значение не расшифровано |
| p[10] | 00 |
| p[11] | Биты 01 вперёд, 02 назад, 04 влево, 08 вправо |
| p[12] | Модуль продольной команды 0…255 |
| p[13] | Модуль команды поворота 0…255 |
| p[14] | 64; постоянное значение из записей, смысл не доказан |
| p[15] | 00 отпустить, 01 опустить, 02 поднять |
| p[16] | 00 |
| p[17] | Предполагаемый свет 0/1 |
| p[18] | Предполагаемый круиз 0/1 |
| p[19…20] | 00 00 |
| p[21] | 01, неизвестный постоянный параметр |
| p[22…23] | 00 00 |
| p[24] | Сумма p[0…23] по модулю 256 |
| p[25] | ED |

Нейтраль после снятия разрешения с p[9]=2:

```text
AA F8 C4 20 00 43 4E 1D 04 02 00 00 00 00 64 00 00 00 00 00 00 01 00 00 9F ED
```

Радиоканал, адрес и фиксированный идентификатор привязаны к предоставленным записям. Это не процедура сопряжения с произвольным роботом. Для другого экземпляра нужны его собственные настройки/идентификатор.
