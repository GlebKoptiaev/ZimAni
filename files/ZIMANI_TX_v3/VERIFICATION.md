# Проверки ZimAni TX 3.0

Дата подготовки: 2026-10-23.

## Выполнено

1. ARM-сборка для Cortex-M4 / STM32F429xx с GCC 12.2.1, `-O2 -Wall -Wextra -Werror`, собственный линкерный скрипт, CMSIS/ST startup. Получены ELF и BIN. Скрипт standalone/build.py повторно собрал идентичный BIN (9832 байта); проверены начальный указатель стека и адрес Reset_Handler в таблице векторов. Размеры секций в приложенном build: text 9828, data 4, bss 6284 байт (bss включает резерв стека 4096 байт).
2. **14 тестов** `tests/test_protocol.py` — прошли. Тесты вызывают скомпилированный C-код `zimani_control.c` через ctypes, а не его отдельную Python-копию.
3. В том числе **1399 из 1399** TX-пакетов воспроизведены байт в байт по соответствующим значениям осей/полей. **1379 из 1379** RX-пакетов проходят проверку рамки, идентификатора и суммы; однобайтовые искажения тестом отклоняются. Эталоны и SHA256 исходных файлов находятся в `tests/capture_vectors.json`.
4. Проверены: CRC16 C/Python, диапазоны и резервные биты, нейтраль перед ARM, наличие связи перед ARM, таймаут ПК, таймаут радио, запрет самовключения после таймаута, новый session, дубликаты/старый sequence, переход uint32 через ноль, изменение p[9] только после снятия разрешения.
5. **7 тестов** Tk-панели с имитацией соединения — прошли: подтверждение ARM, отправка осей/функций, центрирование отключённых ползунков, отсутствие свежего статуса, снятие разрешения платой, задержанные статусы, пауза цикла, закрытие порта при ошибке записи. Некоторые сценарии объединены в одном тесте. Сводный вывод — `build/gui_tests.txt`.
6. Python-модули проходят синтаксическую компиляцию. Аппаратные назначения CN11 и DMA1 сверены по документации ST.

## Не проверено на оборудовании

- Электрическая работа SPI/UART/DMA на вашей Nucleo, питание и совместимость конкретного радиомодуля.
- Радиодоставка и переход TX→RX с реальным роботом; точные интервалы исходного пульта неизвестны.
- Физические направления/скорости, нейтраль, круиз, свет, высота ножа, поведение штатного failsafe.
- Python GUI на Windows: программные тесты выполнялись под Linux/Tk с виртуальным дисплеем и имитацией связи.

Готовый образ — сборка для стендовой проверки, а не подтверждённая аппаратными испытаниями замена штатной системы управления. Порядок подключения и первого запуска приведён в README_RU.md.

## Повтор тестов

`python tests/test_protocol.py` — нужен локальный C-компилятор `cc` (либо путь в переменной CC), тест создаёт временную разделяемую библиотеку. Этот запуск ориентирован на Linux/macOS с POSIX-компилятором; Windows-пользователю он не требуется для работы панели.

`python tests/test_gui.py` — нужен Tkinter, pyserial и графический дисплей. Реальные COM-порты не открываются. Тесты не передают команды роботу.
