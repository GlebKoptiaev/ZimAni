# NUCLEO-F429ZI — пассивный SPI-регистратор v2.0 HW

Версия для проверки на вашей шине. Исправляет архитектурное ограничение v1: границы транзакций теперь сохраняет таймер с DMA, без прерывания на каждую короткую паузу CSN. Код скомпилирован для Cortex-M4, проверки логики выполнены; аппаратно эта версия ещё не испытана. Это исходники для существующего проекта CubeIDE, не готовый .elf/.bin и не полный проект.

## Почему нужна новая версия

На присланной диагностике: TIM2=84 МГц, минимум CSN HIGH — 20 тактов (0,238 мкс). Измеренная часть обработчика v1 — 163 такта процессора 168 МГц (0,970 мкс), без полной стоимости входа/выхода. Следовательно, программная обработка не помещается в такую паузу. Это объясняет остановку v1. Само измерение не доказывает отсутствие помех или правильность определения сигналов.

Три входа CSN дали одинаковые выборки, 34954 из 34998 — высокий уровень. Постоянное замыкание этой линии на землю в момент измерений с этим не согласуется. Звуковой сигнал мультиметра сам по себе не доказывает замыкания: для проверки сопротивления отключите аккумулятор и USB, отсоедините анализатор, измерьте сопротивление в обеих полярностях. Не измеряйте сопротивление на запитанной плате.

## Обязательное изменение проводов

Полностью отключите питание пульта/робота и USB Nucleo перед изменением проводов.

1. Отсоедините CSN от PA0 (CN11, контакт 28), включая старую перемычку с другими контактами CSN. Перенесите это ответвление CSN на PB3 (CN12, контакт 31). Обратите внимание: CN12, а не CN11.
2. Теперь подведите к освободившемуся PA0 (CN11-28) дополнительное ответвление SCK.
3. CSN и SCK должны оставаться разными электрическими цепями. Соединяются только входы одной строки таблицы.

| Сигнал исследуемой платы | Все входы Nucleo для этой линии | Контакты Nucleo |
|---|---|---|
| CSN | PA15, PE4, PB3 | CN11-17, CN11-48, CN12-31 |
| SCK | PC10, PE2, PA0 | CN11-1, CN11-46, CN11-28 |
| MOSI, контроллер → радиомодуль | PC12 | CN11-3 |
| MISO, радиомодуль → контроллер | PE6 | CN11-62 |
| GND | GND | CN11-19 |

Это номера контактов разъёмов CN11/CN12, не номера ножек корпуса микросхемы и не CAN. На плате с USB ST-LINK сверху CN11 расположен слева, CN12 справа. Сверяйте маркировку и таблицу UM1974, а не только считайте отверстия по фотографии.

Радиомодуль продолжает питаться от своей платы. Не соединяйте его VCC с питанием Nucleo. CE и IRQ для этой записи не подключаются. Для данной схемы нужны логические уровни около 3,3 В, общий GND и короткие ответвления. Провод питания 14,8 В к сигнальным входам не подключается. При проверке пульта исключите движение робота, отключив силовое питание приводов.

PB3 используется как TIM2_CH2: отладка только SWD, без SWO/полного JTAG. PA1 не используется, поскольку на этой Nucleo он связан с Ethernet REF_CLK. Ethernet и другие пользовательские функции во время записи не инициализируются.

## Прошивка в существующий CubeIDE-проект

1. Сохраните копию своего текущего Core/Src/main.c и старой прошивки.
2. Замените содержимое Core/Src/main.c файлом main.c из этого архива. Не вставляйте C-код в startup_stm32f429zitx.s. Не добавляйте вторую копию main.c в проект.
3. Используйте проект STM32F429ZITx с обычными CMSIS/HAL файлами, startup и linker script. Буферы должны находиться в обычной SRAM, не в CCM: DMA не имеет доступа к CCM.
4. Если в stm32f4xx_it.c остался добавленный вручную вызов обработчика старого регистратора, удалите именно этот вызов. Здесь EXTI0 не используется. Стандартные обработчики CubeMX можно оставить; HAL_Init не вызывается, периферия настраивается самим main.c.
5. В Properties → C/C++ Build → Settings → MCU GCC Compiler → Optimization задайте -O2 для конфигурации, которую собираете. В логе компиляции main.c проверьте -DSTM32F429xx и -O2. Сообщение optimization_enabled=1 само по себе не отличает -O1 от -O2.
6. Project → Clean, затем Build Project. Подключите верхний USB CN1 около ST-LINK. Прошейте тем же способом, которым успешно прошивали v1.2. При запуске через Debug нажмите Resume либо завершите сеанс и нажмите Reset на плате, чтобы программа работала.
7. В терминале 115200, 8N1, без flow control после Reset должна появиться строка F429 SPI RECORDER v2.0 HW. Наличие этой строки подтверждает запуск новой программы. При старте два раза вспыхивают три пользовательских светодиода.

Перегенерировать .ioc для этой версии не требуется: генерация может заменить main.c. Если раньше включали SWO trace, отключите его.

## Запись через уже работающий PowerShell-терминал

Используйте прежний терминал; новые команды ему подходят.

- h — справка и новое подключение;
- a — ожидание спокойного состояния CSN=1/SCK=0, затем запись до 1 секунды или до заполнения буфера, затем текстовая выгрузка;
- s — остановить текущую запись; в простое диагностических измерений v1.2 больше нет;
- d — повторить последнюю выгрузку, без нового захвата.

Переключите раскладку на английскую. Зафиксируйте нужное положение джойстика до команды a: при активном обмене буфер может заполниться гораздо раньше секунды. После записи ждите #END и READY, выгрузка может занимать несколько секунд. Записывайте нейтраль, вперёд, назад и повороты отдельными захватами.

Успешный результат: flags=0x00000000, frames>0, complete_bytes>0, строки F,... и #END. Синий светодиод означает полные байты без обнаруженных ошибок регистратора; это ещё не доказательство расшифровки смысла команд. Зелёный мигает при работе программы, горит во время ожидания/записи. Красный постоянно — ошибка; короткий красный импульс — полных байтов нет.

## Python: сохранение и разбор

Применяйте reader.py именно из этого архива: он понимает версии 1 и 2. Старый декодер v1 может отвергать новый формат. Закройте PowerShell-терминал клавишей q, чтобы он освободил COM-порт. В каталоге с reader.py выполните (замените COM5 своим номером):

```powershell
python -m pip install pyserial
python reader.py record --port COM5 --out neutral_01.txt
python reader.py decode neutral_01.txt --out neutral_01.csv
```

record сам отправляет a. До запуска установите нужное положение органа управления. Даже ошибочный захват сохраняется в .txt; декодер по умолчанию отвергает ненулевые flags. Для изучения сохранённого префикса можно добавить --allow-partial, но такой результат не считается исправной записью.

Декодирование команд предполагает совместимость радиочипа с nRF24. Физическая запись SPI от этого предположения не зависит. В пульте исходящий пакет обычно ищут в MOSI команды W_TX_PAYLOAD; в приёмнике входящий — в MISO команды R_RX_PAYLOAD. При двустороннем обмене встречаются оба направления и ACK payload. Наличие названий команд ещё не подтверждает модель радиочипа. Названия direction robot_to_radio/radio_to_robot сохранены для совместимости CSV; robot здесь означает контроллер в месте подключения, в том числе контроллер пульта.

## Формат v2 и ограничения

SPI mode 0, MSB first, 8 бит. Два SPI-приёмника в slave RXONLY записывают оба направления через DMA. TIM2 считает на PA0 возрастающие фронты SCK через ETR; по возрастанию CSN на PB3 фиксирует счётчик в CCR2, DMA сохраняет его в массив границ. IRQ на границу кадра нет.

```text
#BEGIN version=2 reason=WINDOW flags=0x00000000 frames=1 complete_bytes=3 raw_mosi=3 raw_miso=3 raw_frames=1 total_sck=24 timestamps=none
#F,index,end_sck,MOSI_hex,MISO_hex
F,0,24,A01122,0E0000
#END
```

Пример иллюстративный, не результат аппаратного испытания. end_sck — накопленное число тактов SCK с начала захвата, НЕ микросекунды. В CSV end_us пуст, end_sck заполнен. Временные интервалы между транзакциями эта версия не сохраняет.

Требуется выделенная шина: такты SCK при CSN=1 не поддерживаются, поскольку TIM2 считает все фронты. На общей SPI-шине с другими устройствами этот метод напрямую не годится. Размеры: 32768 байт на каждое направление, 2048 границ CSN. Незавершённый хвост транзакции не выдаётся как полный кадр.

Синхронизаторы входов и DMA имеют пределы быстродействия. В частности, очень короткое время от последнего SCK до CSN может дать смещение счётчика на границе. Проверка кратности восьми и диапазонов отбрасывает такие явно неверные границы; электрические искажения, которые сохраняют эти условия, могут остаться незамеченными. Предельная частота этой реализации на реальной проводке не измерена.

Таймер и два SPI останавливаются последовательно, не атомарно. Остановка ровно на границе байта может дать консервативную ошибку RX counts / SCK total. В этом случае повторите запись и сохраните ошибочный лог для анализа; не снимайте проверку flags ради синего светодиода.

| Бит flags | Значение | Значение ошибки |
|---|---|---|
| 0 | 0x01 | Граница не кратна 8 тактам |
| 1 | 0x02 | Перезапись capture-регистра TIM2 до чтения DMA |
| 2 | 0x04 | Количество байтов двух SPI различается |
| 3 | 0x08 | Переполнение SPI RX |
| 4 | 0x10 | Ошибка DMA |
| 5 | 0x20 | Не удалось дождаться спокойного старта за 3 секунды |
| 6 | 0x40 | Граница за пределами данных или уменьшение счётчика |
| 7 | 0x80 | Общее количество SCK не совпало с байтами SPI, возможен сдвиг при остановке |

Несколько битов суммируются. Значение 0x01 в v2 имеет другой смысл, чем в v1! Если ошибка остаётся, пришлите строку #BEGIN, #ERROR и первые строки F, а также подтвердите новое подключение. По одной строке raw_mosi без границ нельзя надёжно восстановить команды.
