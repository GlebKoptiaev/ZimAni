# Запись SPI на стороне робота — NUCLEO-F429ZI

Версия 1, 09.10.2026. Плата: NUCLEO-F429ZI / MB1137, STM32F429ZIT6.

Это исходный код специализированного пассивного регистратора SPI, а не универсальный логический анализатор. Он записывает обмен МЕЖДУ радиомодулем и процессором РОБОТА. Программа не передаёт радиокоманды, не меняет прошивку робота и не управляет его SPI.

В архиве: `main.c`, `reader.py`, `test_reader.py`, эта инструкция. Базовый проект, startup, CMSIS и linker script создаёт CubeMX. Это не готовый проект `.ioc`.

## 1. Что регистрируется

Контроллер робота остаётся единственным ведущим SPI. Он формирует SCK, CSN и MOSI. Радиомодуль отвечает на MISO. Анализатор параллельно подключается к этим же линиям.

- SPI3 в STM32 принимает MOSI: команды контроллера робота радиомодулю.
- SPI4 принимает MISO: ответы радиомодуля и принятые радиопакеты.
- Оба SPI работают как slave receive-only, mode 0, 8 бит, MSB first.
- DMA записывает оба потока в два линейных буфера по 32768 байт.
- По положительному фронту CSN сохраняются конец транзакции и приблизительная временная метка. Записывается до 2048 транзакций.
- TIM2 аппаратно считает фронты CSN. Сравнение с числом обработанных прерываний помогает обнаружить пропущенные границы.
- После захвата данные передаются текстом через встроенный ST-LINK Virtual COM Port, 115200 8N1. Отдельный USB–UART не нужен.

Буферы должны находиться в основной SRAM по адресам 0x20000000…0x2002FFFF, не в CCM по 0x10000000. Стандартный linker script для F429ZI размещает обычную `.bss` в основной SRAM. Потребление буферов — около 80 КиБ.

## 2. Подключение

Сначала прошить и проверить Nucleo БЕЗ подключения к роботу. Перед монтажом снять питание с обеих плат. Первые измерения на роботе делать при исключённом движении приводов.

Подтвердить распиновку радиомодуля и напряжение сигналов измерениями. Для этого варианта используйте логические уровни 3,3 В. Не подключать к силовым выходам, CAN-H/L, RS-485 A/B или питанию 12/24/48 В.

| Сигнал между радиомодулем и процессором робота | Контакт Nucleo | Вывод МК | Назначение |
|---|---|---|---|
| SCK | CN11-1 | PC10 | SPI3_SCK |
| SCK, та же линия, второе ответвление | CN11-46 | PE2 | SPI4_SCK |
| MOSI, контроллер → радиомодуль | CN11-3 | PC12 | SPI3_MOSI, вход анализатора |
| MISO, радиомодуль → контроллер | CN11-62 | PE6 | SPI4_MOSI, вход анализатора |
| CSN | CN11-17 | PA15 | SPI3_NSS |
| CSN, второе ответвление | CN11-48 | PE4 | SPI4_NSS |
| CSN, третье ответвление | CN11-28 | PA0 | EXTI0 и счётчик TIM2_ETR |
| GND радиомодуля | CN11-19 | GND | Общий провод |

Да, MISO робота подключается именно к MOSI второго SPI анализатора: в режиме slave это вход данных. Не подключать MISO робота к выходам SPI анализатора PC11/PE5.

На твоей плате CN11 — крайний левый двухрядный ряд отверстий, если держать плату компонентами к себе и разъёмом ST-LINK USB сверху. Часть отверстий на фото без гребёнки: можно впаять контакты. CN11-1 обозначен квадратной площадкой/цифрой 1; в одном ряду нечётные номера, в другом чётные. Не путать CN11 с расположенными рядом чёрными колодками CN8/CN9. Перед пайкой сверить маркировку CN11 и таблицу UM1974.

Сделать ответвления короткими (желательно несколько сантиметров), с коротким общим проводом. Nucleo питается от своего USB, робот — штатно. Соединять только сигналы и GND: линии +3,3 В/+5 В двух плат не объединять. Не оставлять работающий робот подключённым к обесточенной Nucleo. При работе от стационарного компьютера учитывать, что USB GND связан с землёй компьютера; при неизвестных потенциалах нужна соответствующая гальваническая развязка.

В опубликованной документации AS01-ML01DP5 выводы имеют назначения: 1 GND, 2 VCC, 3 CE, 4 CSN, 5 SCK, 6 MOSI, 7 MISO, 8 IRQ. Это НЕ указание ориентации восьми площадок на твоей плате KOHAM. Не считать их слева направо по фотографии без проверки. CE и IRQ в этой версии не записываются.

## 3. Создание проекта в STM32CubeMX

CubeMX генерирует проект; компилирует CubeIDE; прошивает CubeIDE или CubeProgrammer. Через один CubeMX прошить программу нельзя.

1. Установить STM32CubeMX и STM32CubeIDE. При необходимости установить драйвер ST-LINK и пакет STM32CubeF4.
2. В CubeMX выбрать **New Project → MCU Selector**, найти **STM32F429ZIT6** (в списке может отображаться **STM32F429ZITx**), корпус LQFP144.
3. Использовать MCU Selector без автоматической инициализации всех интерфейсов платы. ETH, USB, FreeRTOS не включать.
4. В **System Core → SYS → Debug** выбрать **Serial Wire**. PA13 и PA14 оставить отладчику. Полный JTAG не нужен, потому что PA15 используется для NSS.
5. Остальные настройки можно оставить исходными. SPI, DMA, GPIO, UART и тактирование полностью настраиваются в приложенном `main.c` через регистры CMSIS. **Не надо отдельно включать SPI/DMA/EXTI в CubeMX для этой версии.** Иначе можно получить дублирование обработчика EXTI0.
6. В **Project Manager** задать имя `RobotSpiRecorder`, путь без кириллицы и Toolchain/IDE **STM32CubeIDE**.
7. Нажать **Generate Code**. Если предложена загрузка STM32CubeF4, разрешить её.
8. Открыть сгенерированный проект в CubeIDE. Если он не появился автоматически: **File → Import → General → Existing Projects into Workspace**, выбрать каталог с `.project`.
9. Полностью заменить **Core/Src/main.c** приложенным `main.c`. Не вставлять второй `main()` в существующий файл. Остальные файлы оставить от CubeMX.
10. В **Project → Properties → C/C++ Build → Settings → MCU GCC Compiler → Optimization** выбрать **Optimize for speed (-O2)**. Структура меню зависит от версии IDE. Нужна именно оптимизированная сборка обработчика границ, а не `-O0`.
11. **Project → Build Project**. Должен появиться `.elf` в папке выбранной конфигурации `Debug` или `Release`.

После замены `main.c` повторный Generate Code может перезаписать его: храни исходник отдельно и при повторной генерации снова копируй приложенный файл.

Почему настройка сделана в коде: SPI/DMA/EXTI должны быть согласованы, а повторное включение периферии HAL-кодом может изменить режимы пассивного приёма. Проект использует заголовки CMSIS, которые входят в сгенерированный проект. HAL_Init не вызывается. Generated SysTick_Handler можно оставить: SysTick отключён, для времени используется TIM5.

Clock Configuration в `.ioc` не описывает фактическое тактирование этой самостоятельной версии main.c. Код включает внутренний HSI 16 МГц и PLL: SYSCLK 168 МГц, APB1 42 МГц, APB2 84 МГц. Временные метки имеют точность HSI, это не метрологический прибор.

## 4. Прошивка Nucleo

1. Подключить кабель с передачей данных к **верхнему USB CN1 возле ST-LINK**, противоположному Ethernet-разъёму. Нижний User USB для этой программы не используется.
2. Для программирования встроенного F429 обе перемычки **CN4** должны быть установлены. Питание от USB ST-LINK — штатная конфигурация **JP3 U5V**, JP5 IDD установлен. Проверить позиции по надписям на плате; не ориентироваться только на направление фотографии.
3. В Windows должен появиться **STMicroelectronics STLink Virtual COM Port (COMx)**. Запомнить номер порта.
4. В CubeIDE нажать **Run → Debug As → STM32 C/C++ Application**, выбрать **ST-LINK / SWD**. IDE соберёт и загрузит проект в Flash именно Nucleo.
5. Если выполнение остановилось на `main()`, нажать **Resume**. Во время измерения не ставить breakpoints и не останавливать процессор: это нарушает регистрацию.
6. Для обычного запуска можно использовать Run либо после загрузки выйти из отладки и нажать Reset B2.

Вариант через CubeProgrammer: выбрать ST-LINK → SWD → Connect, открыть собранный `.elf`, выполнить Download с Verify и затем Run/Reset. Для `.elf` адрес берётся из файла. Если используешь `.bin`, начальный адрес Flash — **0x08000000**. CubeProgrammer не компилирует `main.c`.

Если ST-LINK не определяется: проверить USB-кабель, CN1, CN4 и питание; установить драйвер. Если COM есть, но текста нет: проверить 115200 8N1, запустить программу/нажать Reset, убедиться, что используются штатные соединения ST-LINK VCP с PD8/PD9 (SB5/SB6). Не перепаивать мосты без необходимости.

## 5. Первая проверка без робота

1. Открыть COM-порт терминалом (например, уже установленным на компьютере) на **115200, 8 бит, без чётности, 1 stop bit, flow control None**.
2. Нажать Reset на Nucleo. Должен появиться текст `F429 ROBOT SPI RECORDER v1`.
3. Отправить символ `h` — появится справка. Enter не обязателен.
4. Без подключённого робота отправить `a`. Через примерно секунду должен выгрузиться блок с `frames=0`, `complete_bytes=0`, `flags=0x00000000`. Эта проверка подтверждает запуск/COM, но не проверяет SPI-приём.

## 6. Запись на роботе

После подключения по таблице включить обе платы, сохранив невозможность движения приводов. Штатный пульт должен быть связан с роботом.

Команды терминала:

| Символ | Действие |
|---|---|
| `a` | Записать новый фрагмент, затем автоматически выгрузить его |
| `s` | Досрочно остановить текущий захват |
| `d` | Повторно выгрузить последний фрагмент |
| `h` | Справка |

Перед `a` включить запись текста терминала в файл. Сначала держать нейтраль. Во время следующей записи менять только одну ось; отдельно сделать записи для вперёд, назад, лево, право, каждой кнопки. Называть файлы по действиям. Если буфер быстро заполняется, сначала удерживать нужное положение, потом запускать `a`.

Окно ограничено `WINDOW_US=1000000` (1 секунда), но память или таблица границ могут заполниться раньше. Программа не гарантирует запись всей секунды на загруженной шине. При непрерывном SCK 10 МГц 32768 байт соответствуют примерно 26 мс активной передачи; при паузах реальное время больше. Частоту SCK этот вариант непосредственно не измеряет.

Чтобы записать инициализацию радио, анализатор должен быть вооружён до начала инициализации процессора робота. Возможность безопасного сброса только контроллера робота нужно выяснять отдельно. Простое выключение пульта не обязательно повторно инициализирует радиочип робота. Не подсоединять провода во время включения ради этого опыта.

## 7. Автоматическая запись и расшифровка на ПК

Нужен Python 3.9 или новее. Закрыть терминал: один COM-порт не может одновременно использоваться двумя программами.

```bash
python -m pip install pyserial
python reader.py record --port COM5 --out neutral.txt
python reader.py decode neutral.txt --out neutral.csv
```

Вместо COM5 указать свой порт. На Linux это обычно `/dev/ttyACM0`. Для декодирования уже сохранённого файла pyserial не требуется.

Пример ИСКУССТВЕННОЙ транзакции, не реальные данные робота:

```text
F,0,12345,61FFFFFF,40112233
```

- `F` — строка транзакции.
- `0` — её номер.
- `12345` — приблизительное время окончания, мкс от старта захвата. Это время обработки IRQ, не точный аппаратный timestamp фронта.
- `61FFFFFF` — MOSI: команда 0x61 и три фиктивных байта для тактирования чтения.
- `40112233` — MISO: сначала STATUS=0x40, затем полезные данные 11 22 33.

Декодер выделит `R_RX_PAYLOAD`, `data_hex=112233`. Именно такие строки на стороне робота содержат принятые радиопакеты. Декодер НЕ знает заранее назначение байтов джойстиков и кнопок, не снимает возможное прикладное шифрование и не доказывает, что каждый принятый пакет является командой движения.

Дополнительно распознаются чтение/запись регистров, TX payload, ACK payload и служебные команды. В CSV сохраняются оба исходных потока, поэтому можно перепроверить любой вывод.

## 8. Проверка качества записи и ограничения

Этот вариант не заменяет осциллограф: он не показывает напряжения, фронты, звон или короткие помехи. Его пригодность к конкретной частоте SCK и паузам CSN нужно проверить на стенде. На реальном роботе код пока не испытан.

Для начального вооружения нужна пауза CSN=1 не менее 20 мкс. Во время приёма границы обрабатываются прерыванием. Если следующая транзакция начинается слишком быстро, программа прекращает захват с ошибкой. Не уменьшай проверки только ради получения `flags=0`: так можно получить убедительные, но неверные байты.

В `#BEGIN` поле `flags` — битовая маска:

| Бит/значение | Причина |
|---|---|
| 0x01 | При фиксации границы CSN уже изменился / началась следующая транзакция |
| 0x02 | Счётчик реальных фронтов CSN не совпал с числом обработанных границ |
| 0x04 | Число байтов двух SPI не совпало либо последний байт ещё не ушёл в DMA |
| 0x08 | Переполнение приёмника SPI (OVR) |
| 0x10 | Ошибка DMA |
| 0x20 | За 3 секунды не удалось найти подходящий момент для старта |

`flags=0` означает «программа не обнаружила перечисленных ошибок», а не доказательство отсутствия помех/битовых ошибок. Неверно подключённый MISO, другой режим SPI или несоответствие радиочипа могут давать формально корректную запись мусора.

`reason=WINDOW`, `BYTES_FULL`, `FRAMES_FULL`, `USER` — нормальные причины остановки. Последняя незавершённая транзакция не выгружается. `raw_mosi/raw_miso` могут быть больше `complete_bytes`: это отброшенный хвост. `reason=ERROR` требует проверки.

Декодер по умолчанию отклоняет блок с ненулевыми flags или незавершённой UART-выгрузкой. Для просмотра сохранённого до ошибки префикса можно явно использовать:

```bash
python reader.py decode capture.txt --out partial.csv --allow-partial
```

Если возникает BOUNDARY/EDGE_LOSS даже при -O2 и коротких проводах, этот способ фиксации границ недостаточно быстр для конкретного обмена. Тогда требуется другая архитектура регистрации/внешний анализатор; менять скорость штатной SPI без документации не нужно. Если OVR/DMA — проверить тактирование проекта и не запускать параллельно Ethernet/USB/RTOS.

## 10. Что прислать для следующего шага

После прошивки — строку `#BEGIN` и несколько строк `F,...`, лучше целые файлы захватов нейтрали и одного отклонения. По ним можно проверить распознавание радиочипа и приступить к сопоставлению байтов с органами управления.
