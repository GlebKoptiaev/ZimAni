# ZimAni TX v4 — интерфейсы

## ПК → STM32: бинарная команда v2

USART3, PD8 TX / PD9 RX, ST-LINK VCP, 115200 8N1. Размер кадра 22 байта. Многобайтные числа little-endian. В штатной панели период отправки около 20 мс. Текстовые команды анализатора `a/s/d/h` здесь не работают.

| Смещение | Размер | Поле |
|---|---|---|
| 0 | 2 | Синхронизация C3 3C |
| 2 | 1 | Версия 02 |
| 3 | 1 | Тип команды 01 |
| 4 | 4 | Session, uint32, ненулевое случайное значение на каждое открытие порта |
| 8 | 4 | Sequence, uint32, увеличивается на 1 для каждого нового кадра |
| 12 | 2 | Forward, int16: −255…+255 |
| 14 | 2 | Turn, int16: −255…+255, положительное = вправо |
| 16 | 1 | Высота: 0 отпустить, 1 опустить, 2 поднять |
| 17 | 1 | Биты 0 ARM, 1 cruise, 2 light, 3 ESTOP, 4 RESET_STOP; биты 5–7 = 0 |
| 18 | 1 | ДВС-код p[9]: 0 ВКЛ-контекст, 2 ВЫКЛ-контекст |
| 19 | 1 | p[10]: 0 нет нажатия, 1 Двигатель +, 2 Двигатель − |
| 20 | 2 | CRC16-CCITT-FALSE байтов 0…19; polynomial 1021, init FFFF, xorout 0000, refin/refout false |

Проверка CRC: строка ASCII `123456789` → 29B1. Контрольная сумма кодируется LE.

Правила приёма:

- Новая session принимается только с ARM=0 и ESTOP=1. Начальное состояние STM32 — STOP, engine=2, все изменяемые команды нулевые.
- В существующей session принимается только sequence, для которого `0 < (new-old) mod 2^32 < 2^31`. Дубликаты, старые кадры, неправильная версия/CRC/диапазоны не продлевают host watchdog.
- ESTOP=1 доминирует над всеми остальными корректно закодированными полями: устанавливает p[23]=1 и нейтрализует команды, включая engine=2. Диапазоны/CRC проверяются до исполнения STOP.
- Очистить защёлку можно **только** отдельным RESET_STOP=1 при ARM=0, ESTOP=0, нулевых осях/высоте/круизе/свете/adjust, engine=2, свежем BB и неразрешённом управлении. Эта команда задаёт p[23]=0 и can_arm=1, но не armed=1.
- После подтверждения снятия STOP нужен отдельный ARM=1 с нейтралью и engine=2. Панель включает органы управления только по подтверждённому armed=1 с sequence не старее запроса.
- Обычный поток ARM=1 или ARM=0 с ESTOP=0 не снимает защёлку. При уже разрешённом управлении ARM=0 вызывает STOP. В состоянии снятого STOP, но до ARM допускаются только нейтральные heartbeat.
- RESET_STOP при armed=1, ненейтральная попытка ARM или некорректное изменение режима ДВС вызывают STOP.
- engine можно менять при armed=1 только если предыдущие и новые команды осей, высоты, круиза и adjust нулевые. Свет не мешает переключению. adjust!=0 разрешён только при engine=0. Вне armed все эти команды нулевые, engine=2.
- Тайм-аут свежих команд 250 мс; тайм-аут проверенного BB 300 мс. ACK счётчик не продлевает link watchdog. Пропадание BB ставит STOP даже после RESET_STOP до ARM.
- Для восстановления после ошибки повторить STOP → отдельный RESET_STOP → подтверждение → ARM в нейтрали. Повторные пакеты RESET_STOP не должны формироваться автоматически.
- Нет времени формирования кадра на ПК. Не ставьте команды заранее в очередь и не воспроизводите старый UART-поток; передавайте только актуальное состояние.

`pc/zimani_protocol.py` содержит `Command`, `encode`, `parse_status` без побочных действий с COM-портом. Пример формирования одного кадра (не отправляет его):

```python
from zimani_protocol import Command, encode
# Только формирование байтов; здесь нет отправки в COM-порт.
stop = encode(123, 1, Command())  # default estop=True, engine=2
release = encode(123, 2, Command(estop=False, reset_stop=True))
arm_neutral = encode(123, 3, Command(estop=False, armed=True))
# Отправлять реальные команды только после описанных проверок/подтверждений.
engine_on = Command(estop=False, armed=True, engine=0)
engine_plus = Command(estop=False, armed=True, engine=0, engine_adjust=1)
```

## STM32 → ПК: текстовый статус v4

Раз в 200 мс идёт строка ASCII `S v=4 ...\r\n`. При старте также выводится строка версии. Не смешивать бинарные команды с текстовым терминалом, который добавляет CR/LF.

| Поле | Смысл |
|---|---|
| session, seq | Последний принятый корректный кадр, включая отклонённую попытку ARM |
| armed | 1 — разрешено; 0 — нейтраль |
| radio | 1 — прошла настройка и проверка регистров радио по SPI |
| fault | Причина текущего состояния; 0 нет, 1 boot, 2 host timeout, 3 link timeout, 4 radio/SPI, 5 arm rejected, 6 UART/DMA, 7 B1, 8 STOP |
| host_ms | Возраст последнего корректного кадра; 999999 если нет свежего |
| link_ms | Возраст последнего валидного BB (ACK не учитывается); 999999 если связь устарела |
| ack | Число TX_DS (с EN_AA=1 — получено аппаратное подтверждение) |
| fail | Число MAX_RT/таймаутов TX |
| rx | Число валидных 23-байтных BB-пакетов |
| badrx | Неверный размер/формат/идентификатор/сумма принятых пакетов |
| reject | Отклонённые кадры ПК, включая старый sequence и ошибки синхронизации/CRC |
| uart, spi | Счётчики обнаруженных ошибок UART/DMA и радио/SPI |
| f, t, blade, cruise, light, engine, adjust, estop | Текущее состояние команды, из которого формируется TX |
| can_arm | 1 — защёлка снята, возможен ARM при соблюдении остальных условий |
| stop_rx | Последний r[11], 255 до первого валидного ответа; только информационное поле |
| rx_ms, reply | Возраст и HEX последнего корректного BB; `-`, если его ещё не было |

ACK подтверждает радиодоставку, но не исполнение двигателями. reply может быть старым — смотрите rx_ms. Ответы BB проверяются по длине, маркерам, идентификатору и сумме; смысл всех телеметрических байтов пока не установлен.

## STM32 → радиомодуль

SPI3 master, mode 0, MSB first, 8 бит, около 1,3125 МГц. GPIO CE — PE3, CSN — PA15. PC10 SCK, PC12 MOSI, PC11 MISO. USART3_RX DMA1 stream1 channel4; TIM5 даёт микросекунды. HSI → PLL 168 МГц, APB1 42 МГц. Уровни 3,3 В. HAL не используется в рабочем цикле.

| Регистр | Записываемое значение |
|---|---|
| CONFIG | 0A при настройке/для TX, 0B для RX; аппаратная CRC 1 байт |
| EN_AA | 01 |
| EN_RXADDR | 01 |
| SETUP_AW | 03 (5 байт) |
| SETUP_RETR | F3 (4 мс, до 3 повторов) |
| RF_CH | 45 (2469 МГц) |
| RF_SETUP | 22 в первом проходе, 23 во втором (250 кбит/с) |
| TX_ADDR | F8 C4 20 43 4E — порядок байтов на SPI |
| RX_ADDR_P0 | F8 C4 20 43 4E |
| DYNPD | 01 |
| FEATURE | 07 |

До настройки TX_ADDR=A5 A5 A5 A5 A5 записывается и читается обратно, затем заменяется рабочим адресом. Два прохода настройки воспроизводят наблюдаемую смену RF_SETUP. Если FEATURE не записался, выполняется ACTIVATE `50 73`, затем повторная запись и проверка. Не предполагается универсальная поддержка всех клонов радио; при несовпадении прочитанных регистров radio=0, движение запрещено.

После PWR_UP выдерживается 5 мс. Для TX загружается `A0` + 26 байт, CE удерживается высоким не менее 20 мкс. STATUS опрашивается; после TX_DS либо ошибки передатчик переходит в RX и принимает ответы через `60`/`61`. RX-FIFO обрабатывается и до смены TX→RX, поэтому поддержан как ACK-payload, так и отдельный ответ робота. На следующем цикле загружается актуальное состояние. Минимальное окно RX — 3 мс; целевой период TX — 20 мс. Таймаут TX — 20 мс; при неудачах период увеличивается. Точное исходное расписание CE по имеющимся записям неизвестно. В новом init_03 BB следует после TX_DS и переключения CONFIG в RX, что указывает на отдельный прикладной ответ в наблюдаемом цикле. Его наличие требуется для ARM; r[11] не считается мгновенным подтверждением остановки.

## Полезная нагрузка команды: 26 байт

p[i] считает байты ПОСЛЕ команды SPI A0.

| Байты | Содержимое |
|---|---|
| p[0] | AA |
| p[1…8] | F8 C4 20 00 43 4E 1D 04; фиксированная часть из ваших записей |
| p[9] | 00 в контексте включённого ДВС; 02 выключенного. Процедура стартера не установлена |
| p[10] | 00 нет нажатия; 01 Двигатель +; 02 Двигатель − |
| p[11] | Биты 01 вперёд, 02 назад, 04 влево, 08 вправо |
| p[12] | Модуль продольной команды 0…255 |
| p[13] | Модуль команды поворота 0…255 |
| p[14] | 64; постоянное значение из записей, смысл не доказан |
| p[15] | 00 отпустить, 01 опустить, 02 поднять |
| p[16] | 00 |
| p[17] | Предполагаемый свет 0/1 |
| p[18] | Предполагаемый круиз 0/1 |
| p[19…20] | 00 00 |
| p[21] | 01, неизвестный постоянный параметр |
| p[22] | 00 |
| p[23] | 00 нет запроса STOP; 01 запрос остановки |
| p[24] | Сумма p[0…23] по модулю 256 |
| p[25] | ED |

STOP после включения и защитной остановки (p[9]=2, p[23]=1):

```text
AA F8 C4 20 00 43 4E 1D 04 02 00 00 00 00 64 00 00 00 00 00 00 01 00 01 A0 ED
```

Радиоканал, адрес и фиксированный идентификатор привязаны к предоставленным записям. Это не процедура сопряжения с произвольным роботом. Для другого экземпляра нужны его собственные настройки/идентификатор.

После явного RESET_STOP при нейтрали p[23]=0, SUM8=9F; это снятая защёлка, но движение ещё не разрешено. Прикладная SUM8 радиопакета и CRC16 UART независимы.

Управление только кодами из расшифрованных записей: p[9]=1 и непроверенные команды стартера не генерируются. Свет и круиз остаются кандидатами с прежними конфликтами меток.
