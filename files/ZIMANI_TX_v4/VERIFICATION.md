# Проверки ZimAni TX 4.0

Дата: 23.10.2026. Это программная проверка и сборка, без физического радиомодуля/робота.

## Выполнено

- ARM GCC 12.2.1, Cortex-M4/STM32F429xx, `-O2 -Wall -Wextra -Werror`: ELF и BIN собраны без предупреждений/ошибок. BIN 10 312 байт; text 10 308, data 4, bss 6444 байта (включая резерв стека). Начальный SP=0x20030000, Reset_Handler=0x08002675 (Thumb); адреса лежат в допустимых областях. Готовая прошивка основана на тех же исходниках Core, которые приложены.
- **26 тестов реального C-обработчика** `zimani_control.c` через ctypes: STOP после старта, явное снятие, нейтраль перед ARM, приоритет STOP, тайм-ауты, запрет самовключения, режим ДВС, удержание +/−, неверные диапазоны/CRC/версия, sequence/session и переполнение uint32. Дополнительно 3000 воспроизводимых случайных переходов проверяют инварианты состояния.
- **2265 TX-payload воспроизведены побайтно**: 1399 старых + 803 новых чистых + 63 из полного префикса ошибочной записи power_off. Последняя группа отдельно помечена в данных. Это проверка генератора payload, не точного расписания SPI/CE и не выполнения команд роботом.
- **2120 RX-payload** проходят проверку структуры, идентификатора и SUM8; тестовые однобайтовые искажения отвергаются.
- **20 тестов Python/Tk GUI** с имитацией соединения: разделение RESET/ARM, ожидание sequence-подтверждения, защита от старого статуса, команды ДВС и удержание, потеря статуса/пауза, перезапуск MCU, несовместимая версия, закрытие порта при ошибке. В одном тесте GUI передаёт байты непосредственно в реальный C-обработчик: снятие STOP → ARM → ДВС → Двигатель − → STOP.
- Python-модули компилируются; GUI визуально просмотрен на виртуальном Linux-дисплее. Внешний вид на Windows зависит от системного Tk/шрифтов.

Подробные результаты: `build/protocol_tests.txt`, `build/gui_tests.txt`.

## Не проверено

- Реальные SPI/UART/DMA и электропитание на вашей плате.
- Радиодоставка, CE/задержки и окно отдельного BB-ответа на конкретном модуле.
- Физический эффект STOP, поведение штатного failsafe и задержка механической остановки.
- Полный цикл стартера ДВС; код p[9]=0 подтверждён только контекстом записи «ДВС включён».
- Окончательная семантика света/круиза и неизвестной телеметрии.
- Запуск GUI на реальной Windows-системе пользователя.

## Повтор проверки

```text
python tests/test_protocol.py
python tests/test_gui.py
```

Первой команде нужен native C-компилятор `cc` (или путь в CC); тесты ctypes ориентированы на Linux/macOS с POSIX-компилятором. Второй нужны Tkinter, pyserial и дисплей; интеграционному тесту также нужен cc. Реальные COM-порты не открываются. Для обычного запуска панели на Windows тестовые зависимости не нужны.

Сборка:

```text
python standalone/build.py --project /path/to/CubeMX_project --gcc /path/to/arm-none-eabi-gcc
```

Нужны CMSIS и ST startup из проекта STM32F429ZI. Исходники сторонних библиотек не включены; сведения о лицензиях сохранены в licenses/.
