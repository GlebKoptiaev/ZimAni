# ZimAni TX 4.0 — NUCLEO-F429ZI и Python-панель

Обновление по дополнительным SPI-записям. STM32 работает как SPI-master штатного радиомодуля пульта. Штатный контроллер пульта должен быть электрически отсоединён. Управление робота остаётся штатным.

## Что изменилось относительно v3

- Добавлены p[9] (код ДВС: 0/2), p[10] (удержание «Двигатель +/−»: 1/2) и p[23] (запрос аварийной остановки: 1).
- STOP, кнопка B1, сброс STM32, тайм-аут ПК или ответа робота устанавливают защёлку: p[23]=1, p[9]=2, p[10]=0, оси/нож/круиз/свет=0. Повторное движение требует отдельного снятия STOP, затем разрешения в нейтрали.
- Для снятия STOP и разрешения требуется свежий **проверенный BB-ответ**. Одного аппаратного ACK теперь недостаточно. Обнаруженный r[11] отображается с возрастом ответа, но не используется как доказательство физической остановки.
- Инициализация проверяет тестовый адрес A5…A5, затем выполняет две настройки RF_SETUP=22 → 23 с рабочим адресом F8 C4 20 43 4E. Это адаптация наблюдаемой последовательности с проверками, не точный временной повтор лога.
- Python-панель и двоичный UART-протокол обновлены совместно: **прошивка v4 требует новый скрипт**. Старые команды UART v1 отклоняются.

Это версия для стендовой проверки. Сборка и программные тесты выполнены; физический радиомодуль и робот в этой среде недоступны. Совпадение payload не доказывает выполнение команд механизмами.

## Быстрое обновление существующего проекта v3

1. Сохраните копию проекта. Остановите Python-панель и отключите силовые исполнительные механизмы для первой проверки.
2. Замените четыре файла проекта: `Core/Src/main.c`, `Core/Src/zimani_control.c`, `Core/Inc/zimani_control.h`, `Core/Inc/zimani_config.h` файлами этого архива.
3. Выполните Clean → Build (`-O2`), прошейте через CubeIDE и нажмите Resume/RESET. Настройки и подключения передатчика v3 сохраняются; схема пассивного анализатора не подходит.
4. Замените **всю папку pc**. Старый скрипт с новой прошивкой не работает.
5. Подключитесь новым скриптом. В статусе должна быть версия 4; после старта красный STOP ожидаем.

Можно использовать готовые `build/ZIMANI_TX_v4.elf` / `.bin` вместо самостоятельной сборки. BIN прошивается по адресу **0x08000000**. В архиве также исходники, тесты, `PROTOCOL.md`, `VERIFICATION.md` и скрипт повторной сборки `standalone/build.py`.

## 1. Переподключение радиомодуля

**Старая схема анализатора для этой прошивки не подходит.** Теперь STM32 сама выдаёт CSN, SCK, MOSI и CE. Модуль должен быть электрически отделён от контроллера штатного пульта: выключение питания его платы само по себе этого не обеспечивает. Иначе возможны конфликт выходов и питание выключенной платы через сигнальные линии. Удобнее извлечь модуль из разъёма и подключить его отдельно.

Уберите прежние ответвления CSN на несколько входов STM32 и ответвления SCK. Подключите каждый сигнал только по следующей таблице. Нумерация 1–8 соответствует присланной вами схеме радиомодуля; при пайке со стороны выводов изображение будет зеркальным. Сверяйте ориентацию по GND/VCC, а не только по расположению антенны.

| Контакт радиомодуля | Назначение | NUCLEO-F429ZI | Контакт CN11 |
|---|---|---|---|
| 1 | GND | Общая земля | 19 |
| 2 | VCC | Отдельное стабилизированное питание **3,3 В** | Не соединять с 5 В/VIN |
| 3 | CE | **PE3**, выход STM32 | **47** |
| 4 | CSN | **PA15**, выход STM32 | **17** |
| 5 | SCK | **PC10**, SPI3 SCK | **1** |
| 6 | MOSI | **PC12**, SPI3 MOSI | **3** |
| 7 | MISO | **PC11**, SPI3 MISO | **2** |
| 8 | IRQ | Не подключать; статус читается по SPI | — |

CN11 — длинный двухрядный разъём/ряд отверстий ST morpho, не CN9 и не надпись CAN. Номера CN11 взяты из UM1974, таблица 21. Если удобнее использовать существующие гнёзда Zio: PC10 = CN8-6, PC11 = CN8-8, PC12 = CN8-10, PA15 = CN7-9, PE3 = CN9-22. Это альтернативные точки тех же сигналов; соединять обе точки не требуется.

**Главное отличие от анализатора: MISO теперь на PC11, а CE добавлен на PE3.** PE6 для MISO здесь не используется. Три входа CSN объединять больше не нужно. CAN не используется.

Питание и монтаж:

1. Проводить пайку при отключённом питании STM32 и радиомодуля.
2. Модулю с усилителем нужен источник 3,3 В с запасом по пиковому току по его документации. Не предполагается, что выход 3V3 Nucleo способен питать ваш модуль с усилителем. Не подавать 5 В или напряжение аккумулятора пульта.
3. Соединить GND источника, радиомодуля и STM32. Не соединять между собой выходы двух стабилизаторов 3,3 В.
4. Рядом с VCC модуля поставить 100 нФ и 10–47 мкФ. Сигнальные провода сделать короткими.
5. Поставить **10 кОм CE–GND**: удерживает CE низким во время сброса STM32. Рекомендуется **10 кОм CSN–3,3 В**.
6. Антенна должна быть подключена перед передачей.
7. Nucleo подключить к ПК через верхний USB CN1 ST-LINK. Нижний User USB для этой прошивки не используется.

При раздельном включении питания не оставляйте активные сигналы STM32 на обесточенном радиомодуле. Перед любыми изменениями соединений отключайте оба источника.

## 2. Сборка и прошивка через STM32CubeIDE

Создайте отдельный проект, чтобы сохранить рабочий анализатор.

1. **File → New → STM32 Project**.
2. Во вкладке MCU Selector выберите **STM32F429ZIT6**. Название проекта, например `ZimaniTransmitter`. Тип проекта — STM32Cube, язык C.
3. Если открывается `.ioc`, сохраните его и выполните Generate Code. Специально настраивать SPI/UART/DMA в CubeMX для этой версии не нужно: их полностью инициализирует предоставленный `main.c`.
4. Замените **только `Core/Src/main.c`** файлом из архива.
5. Скопируйте `Core/Src/zimani_control.c` в `Core/Src`, а оба файла из `Core/Inc` — в `Core/Inc` проекта.
6. `startup_stm32f429zitx.s`, `system_stm32f4xx.c`, папку Drivers и линкерный файл оставьте сгенерированными CubeIDE. **Не вставляйте C-код в startup-файл.** Файлы из `standalone` в проект CubeIDE не копируйте.
7. Обновите дерево проекта клавишей F5. В Project Properties → C/C++ Build → Settings → MCU GCC Compiler → Optimization выберите **Optimize more (-O2)** для собираемой конфигурации. Убедитесь, что определён `STM32F429xx`; новый проект для F429 задаёт его сам.
8. **Project → Clean**, затем **Build Project**. В сборку должны попасть и `main.c`, и `zimani_control.c`.
9. Подключите USB CN1. Выполните **Run → Debug As → STM32 C/C++ Application** со ST-LINK/SWD. После загрузки нажмите **Resume**, если отладчик остановился в `main`.
10. Для самостоятельной работы завершите отладку и нажмите RESET B2 на плате. Не оставляйте процессор на breakpoint во время проверки приводов: штатный watchdog может перезапустить STM32 примерно через секунду.

Если переносить файлы в старый проект анализатора, там могут остаться обработчики прерываний и HAL-дескрипторы от прежнего кода. Чистый проект по инструкции выше избегает таких конфликтов. После замены main.c не запускайте повторную генерацию CubeMX поверх него: она может перезаписать реализацию.

Готовый `build/ZIMANI_TX_v4.elf` также можно загрузить через STM32CubeProgrammer, интерфейс ST-LINK. Для `.elf` адреса берутся из файла; для `.bin` укажите **0x08000000**, включите Verify и после записи Reset/Run. Этот образ предназначен только для STM32F429ZI с указанной разводкой.

## 3. Запуск Python-панели

Нужен Python 3.10+ с Tkinter и pyserial. Обычный Python для Windows включает Tkinter. Закройте другие программы, занимающие ST-LINK COM-порт. Откройте PowerShell в папке `pc`:

```powershell
py -m pip install -r requirements.txt
py zimani_control.py --port COM5 --log test_v4.log
```

Замените COM5 номером STLink Virtual COM Port. Параметры 115200, 8N1 задаются автоматически. При отсутствии `py` используйте `python`. Без `--port` порт можно выбрать в окне; `--log` необязателен.

Порядок работы:

1. Нажмите **Подключить**. Передаётся STOP; сами подключения или перезапуски ничего не разрешают.
2. Дождитесь `radio=1`, увеличения числа ответов BB и возраста BB менее 300 мс. На роботе аварийная кнопка должна быть отпущена, если она отключает его ответ; физическую работоспособность привода проверяйте отдельно.
3. Нажмите **Снять STOP**. STM32 примет однократный запрос только при свежем ответе BB и нейтральных командах. Это подтверждение состояния STM32, не механической остановки/готовности робота.
4. Дождитесь подтверждения, затем нажмите **Разрешить управление**. Элементы управления включатся после `armed=1` от STM32.
5. Начните с малых команд, последовательно проверьте направления и вспомогательные функции.

После любого STOP, потери фокуса окна, разрыва связи, паузы программы или сброса повторите шаги 2–4. Скрипт никогда не повторяет снятие STOP автоматически. Непрерывный поток команд ARM не снимает защёлку.

| Элемент панели | Действие |
|---|---|
| Продольная ось | −255 назад, +255 вперёд; это условные единицы команды |
| Поворот | −255 влево, +255 вправо |
| Поле джойстика | Отпускание мыши центрирует оси; при круизе сохраняется продольная команда |
| Ползунки | Удерживают заданное значение после отпускания |
| Круиз / свет | Передают p[18] / p[17]; прежние оговорки расшифровки остаются |
| Поднять / опустить | Передают p[15]=2 / 1 только при удержании; абсолютная высота не задаётся |
| ДВС: команда ВКЛ / ВЫКЛ | Передают p[9]=0 / 2; разрешены только при нейтрали и без активной команды высоты/круиза/изменения оборотов |
| Двигатель + / − | Передают p[10]=1 / 2 при удержании; требуют разрешённое управление и выбранный код ДВС ВКЛ |
| Отпускание кнопки мыши | Сбрасывает удерживаемые команды высоты и Двигатель +/− |
| Красный STOP / пробел / B1 Nucleo | Защёлкивают p[23]=1, ДВС-код 2, остальные изменяемые команды обнуляются |

**Кнопка «ДВС: команда ВКЛ» задаёт наблюдавшийся код 0; она не обещает полный цикл запуска стартера.** В логах нет полного перехода запуска, поэтому неподтверждённые импульсы или p[9]=1 не добавлены. Значения ДВС на экране — команды, не показания фактической работы двигателя.

Для изменения режима ДВС сначала центрируйте оси, выключите круиз, отпустите кнопки и дождитесь нулевых значений в статусе STM32. Попытка смены режима под нагрузкой на уровне протокола приводит к STOP. При остановке engine=2 задаётся без этого ограничения.

## 4. Индикация и статусы

| Светодиод | Значение |
|---|---|
| Зелёный LD1 / PB0 мигает | Прошивка работает, управление не разрешено |
| Зелёный постоянно | armed=1 |
| Синий LD2 / PB7 | radio=1 и свежий проверенный BB-ответ; аппаратного ACK недостаточно |
| Красный LD3 / PB14 | STOP защёлкнут, ошибка или радиомодуль не настроен |

`radio=1` означает успешную проверку регистров по SPI. `ack` — число аппаратных подтверждений; `rx` — принятые корректные BB-пакеты; `link_ms` — возраст последнего такого BB, не ACK. `stop_rx` — последний r[11]; 255 означает, что корректного ответа ещё не было. Смотрите вместе с `rx_ms`; старое значение не описывает текущее состояние.

Причины `fault`: 0 нет; 1 старт; 2 тайм-аут Python; 3 нет BB-ответа; 4 SPI/радиомодуль; 5 неверная процедура разрешения/команда; 6 UART; 7 кнопка B1; 8 команда STOP. При регулярных STOP-пакетах от панели fault=8 может заменить первоначальную причину; первоначальный переход сохранится в логе, если его статус успел прийти.

Если ACK растёт, но BB нет, управление останется запрещённым: проверьте переход TX→RX, адрес/канал и состояние робота. Обход этого условия в панель не добавлен. Если физическая аварийная кнопка робота подавляет ответ, отпустите её только в подготовленных условиях испытания; при нажатой кнопке снятие программного STOP может быть невозможно.

## 5. Период и ограничения остановки

Номинальный цикл радио 20 мс — проектный параметр, не измеренная частота оригинального пульта. При повторах TX цикл растягивается; после TX предусмотрено окно RX не менее 3 мс. CE при передаче удерживается не менее 20 мкс. Эти интервалы надо проверить на оборудовании.

Python передаёт команды примерно каждые 20 мс. При паузе своего цикла более 200 мс, потере фокуса или отсутствии статуса STM32 около 700 мс панель ставит STOP. STM32 независимо ставит STOP после 250 мс без свежих корректных команд или 300 мс без корректного BB-ответа. Старые sequence/неверный CRC не продлевают тайм-аут.

При потере связи STOP остаётся защёлкнутым и повторяется после восстановления. Уже запущенный радиопакет может завершиться до следующего STOP-пакета: текущая передача не прерывается посреди аппаратного ACK. При потере питания/радиоканала доставка STOP не гарантируется — требуется штатный failsafe робота и независимый физический аварийный останов. r[11] не используется для ожидания перед отправкой STOP.

Проверяйте на стенде: STOP, B1, закрытие окна, отключение USB, пропадание BB при сохранении ACK, потерю/восстановление питания передатчика и радиоканала. Автоматического возобновления движения быть не должно.

## 6. Радиоконфигурация

Рабочий адрес в SPI-порядке F8 C4 20 43 4E; RF_CH=45; RF_SETUP=23; CONFIG=0A для TX и 0B для RX; EN_AA=01, EN_RXADDR=01, SETUP_AW=03, SETUP_RETR=F3, DYNPD=01, FEATURE=07.

Тест A5…A5 проверяется до рабочих адресов. ACTIVATE 50 73 используется только как резервный путь, если FEATURE не записывается; в новых логах эта команда не наблюдалась. При одиночном MAX_RT прошивка очищает TX и возвращается к RX, а не повторяет весь стартовый обмен как оригинальный пульт. Ошибка SPI приводит к STOP и повторной инициализации через 1 с. Это намеренное поведение эмулятора, а не побайтовый проигрыватель SPI-файла.
